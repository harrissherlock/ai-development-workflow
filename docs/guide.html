1. 功能介绍

AI 开发协作（ai-development-workflow）把 ChatGPT Work、GitHub、GitHub Actions 和 Vercel 的开发过程组织为可复用流程。当前采用交互式开发，保留未来后台 Agent 接入所需的任务与项目记录。

功能处理内容
识别项目读取仓库结构、AGENTS.md、依赖、测试命令及已有部署配置。
实现与修复在任务分支修改代码，保留用户已有修改，持续处理相关问题。
验证行为执行适当的测试、构建和页面检查，区分执行成功与尚未验证。
交付 PR创建或更新 PR，检查与当前提交对应的 CI 结果。
检查预览获取真实 Vercel 预览地址，核对部署版本并检查重要交互。
支持交接记录任务、分支、提交、检查结果及剩余工作，便于未来更换执行者。

2. 使用前准备

  • 连接目标 GitHub 仓库，并提供开发需要的读取及写入权限。
  • 将 Web 项目连接到 Vercel，配置对应的构建命令、输出目录和环境变量。
  • 配置 GitHub Actions 自动检查，优先复用仓库已有测试。
  • 提供仓库地址和明确需求。已有项目规范、Issue 或 PR 时，同时提供其位置。

Skill 提供执行流程；实际终端、网络、账号权限和部署能力由当前环境提供。首次使用会先检查这些条件，再完成当前可执行的工作。账号密钥通过平台凭据或环境变量管理。

3. 如何调用

在对话中选择 AI 开发协作，或在消息中明确指定名称：

使用 $ai-development-workflow，为这个仓库增加日历视图。支持月视图、周视图和拖动任务修改日期。完成相关测试后创建 PR，并提供对应提交的 Vercel 预览地址。仓库：填写你的仓库地址。

建议同时说明功能要求、数据保存方式和完成条件。需要继续已有任务时，给出原 PR 或 Issue，助手会读取最新状态后继续。

使用 AI 开发协作，继续处理 PR #42。任务卡片改为紧凑显示，拖动时显示目标日期，检查修改后的数据是否正确保存。

Skill 列表尚未显示时，可以刷新或重新打开 Skills 页面。

4. 开发样例与实际体验

样例：FocusOS 日历功能

1. 描述需求

给 FocusOS 增加日历视图，支持月视图、周视图和拖动修改任务日期，并与现有任务系统同步。

2. 查看开发进度

助手检查数据结构和已有命令，创建或复用开发分支，实现功能并运行相关检查。开发过程中会汇报关键结果，你可以随时补充需求。

3. 打开实际预览

助手交付真实 PR 地址、检查结果和当前提交对应的预览地址。预览检查覆盖视图切换、日期修改、保存及刷新后的结果。

4. 继续调整

周视图增加时间轴，移动端提供点击修改日期的入口。

助手继续更新同一任务分支，重新运行相关检查，核对更新后的部署。

5. 确认合并

检查效果后，你发出合并指令。助手在具备权限时检查当前状态并执行。项目已配置正式分支自动部署时，Vercel 随后发布正式版本。

提出需求 → 交流与开发 → 自动检查 → 查看预览 → 调整细节 → 确认合并。

本节为使用流程示例，未创建实际日历功能或 PR。

5. 交付内容与检查标准

  • 变更说明：说明用户可以使用的新行为或已修复的问题。
  • 检查结果：列出实际执行的检查，明确通过、失败或尚未执行。
  • PR 地址：有权限完成时提供真实链接。
  • 预览地址：核对提交和部署状态后提供真实链接。
  • 需要处理的事项：明确缺失权限、外部服务故障或未完成的验证。

旧提交的部署成功结果不会作为新提交的验证结果。测试失败时继续分析并修复相关问题；无法访问的外部服务会明确说明，同时完成独立可执行的检查。

6. 未来兼容后台 Agent

当前开发由 ChatGPT Work 执行。后续可以加入 OpenHands 等后台 Agent，共用仓库规范、Issues、PR、CI 和 Vercel。

已保留的设计未来用途
项目 AGENTS.md 模板保存安装、运行、测试及协作说明。
便携任务记录保存目标、完成条件、负责人、分支、提交和进度。
一个任务分支由一个执行者修改减少同时修改引起的冲突，支持明确交接。
按提交检查 CI 和预览后台执行者使用同样的检查方法。

未来后台运行需要额外接入任务调度、状态保存、失败重试与费用限制。当前 Skill 不会持续监听 GitHub，也不会在关闭会话后自动启动修复服务。

7. 常见问题

是否需要自己开发 MCP 或插件？

当前复用已有 GitHub 和 Vercel 工具。遇到现有工具无法覆盖的实际需求时，再增加自定义接口。

是否自动合并和发布？

默认交付 PR 和预览。合并及正式发布按你的明确指令执行。预览部署采用项目已有配置。

能否用于其他项目？

可以。每次指定目标仓库，助手根据实际技术栈、命令和部署方式执行；不会固定使用 FocusOS 配置。

是否已配置我的 GitHub 和 Vercel？

本次创建的是 Skill 和使用文档。项目连接、自动检查及部署设置在你要求配置具体仓库时进行检查和修改。

包含哪些资源？

包含核心执行说明、验证策略、CI 与预览交付规则、后台 Agent 兼容说明，以及任务记录和 AGENTS.md 模板。
